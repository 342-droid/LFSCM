## 规则说明

后续新增或改造 **C 端多状态 / 多分支演示能力**（如黑名单禁用项、注册有礼条件、活动门槛等），除非另有说明，一律提供右下角（或与既有面板错开的固定角）**验收开关面板**，方便业务同事自行切换查看效果。

### 必须

1. **悬浮验收面板**：小卡片固定在视口角（默认右下；若同页已有面板则改左下或上移，避免重叠）。
2. **标题命名**：`xxx验收开关`（如「注册有礼验收开关」「黑名单验收开关」）。
3. **控件形态**：下拉 / 勾选表达状态；底部橙色主按钮「应用并刷新…」写入 localStorage 后刷新页面生效。
4. **视觉对齐**：白底、浅边框、圆角、轻阴影；字号约 11–12px；主按钮 `#ff7019`（对齐既有 `ua-rg-demo`）。
5. **可叠加门禁**：若页面会被业务态锁死（如禁访问），验收面板须保持可点（`z-index` 更高 + `pointer-events: auto`），以便切回正常态。
6. **状态持久化**：用独立 `localStorage` key；可选支持 URL 参数做一次写入，避免只能改代码验收。

### 建议

- 提供「关闭演示 / 跟随真实数据」开关，关掉后走正式联调数据（B 端配置、会员档案等）。
- 勾选语义写清（如「勾选 = 禁用该项」），减少误读。

## 例外

- 仅单次、单路径的临时调试（如一次性 `?xxx=1`）可不做面板，但若同一能力后续会反复验收多状态，应补上面板。
- B 端后台配置页本身不套用本 C 端悬浮面板样式。
