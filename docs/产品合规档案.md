## 1. 需求描述

### 1.1 供应链-主数据，产品合规档案

对部分需合规管控的商品，建设以 **注册证号 / 备案号** 为中心的 **产品合规档案包**；可复用证照落在 **资质主体（供应商增强）**；按 **合规模板** 定义必证清单并支持可视化配置（增删项、新管控类型）。系统计算齐套与效期状态，供商品详情、供货关系只读消费。

**本期不做**：生产批号、批次效期追踪、召回路径、物流节点、一物一码等批次溯源能力。文案统一使用「合规 / 资质 / 档案包」，不使用「溯源」。

### 1.2 逻辑说明

#### 1.2.0 模型与原则

```
合规模板（管控类型 → 必证/选证清单）
        │
资质主体（供应商）──持有──► 主体证照
        │                      │ 引用
        └──────────────────► 产品合规档案包 ──映射──► 货号（基础商品）
                                ├── 包头（证号、品名、委托方、生产方、效期…）
                                └── 包内专属附件（注册证/备案/检测…）
```

1. **档案包是业务主容器**；以注册证号或备案号为业务主键叙事。
2. **主体证照一处维护、多包引用**；商品不直接「拥有」工厂执照。
3. **模板是规则**：定义清单项来源（主体引用 / 档案包上传）、必要程度、是否效期预警。
4. 主路径：**一个档案包映射 N 个货号**；特妆常见 **一色号一证号一货号**。
5. 商品与供货关系 **消费** 齐套/效期聚合状态；一期卡点默认不拦截启用。

#### 1.2.1 字典与全局配置

**管控类型**

- 由「合规模板」维护；每条启用中的模板对应一个管控类型（编码 + 名称）。
- 预置两条（可改名、停用，不可删编码若已被档案包引用时可仅停用）：
  - `COSMETIC_SPECIAL`：特殊化妆品
  - `COSMETIC_NORMAL`：普通化妆品

**主体证照类型（系统字典，一期写死可扩展列表）**

- 营业执照、生产许可证、商标注册证、法人证件人像面、法人证件国徽面、食品经营许可证、其他

**清单项来源**

- `subject_ref`：主体引用（从委托方或生产方已维护证照中选择）
- `dossier_upload`：档案包上传（本包专属附件）

**主体角色约束（引用项用）**

- 委托方、生产方

**全局预警天数**

- 配置项：到期前 N 天视为「即将过期」，默认 `60`；在合规模板列表页或档案列表页提供「预警设置」入口（一期放在合规模板页顶部即可）。

**卡点开关（一期可配置，默认如下）**

| 开关               | 默认 | 说明          |
| ---------------- | -- | ----------- |
| 允许不齐套仍将档案设为生效    | 开  | 生效后齐套可为「缺失」 |
| 管控商品无生效映射时标「未建档」 | 开  | 仅展示         |
| 供货关系启用须商品合规=齐全   | 关  |             |
| 商品启用须合规=齐全       | 关  |             |

#### 1.2.2 合规模板（可视化配置 · 一期必做）

原型：`SCM/master_data_compliance_template.html`  
新建/编辑：**列表页内弹窗**（非跳转整页）。清单项采用「摘要列表 + 嵌套编辑层」，避免九列并排挤在弹窗里。

##### 列表

- 标题「合规模板」；按钮「+ 新建模板」「预警设置」
- 查询：模板名称、管控类型编码、状态（全部/启用/停用）
- 列：管控类型编码、模板名称、清单项数（必填数/总数）、状态、更新时间、操作
- 操作：编辑、启用/停用；**无删除**（已被档案包引用的不可停用时提示「已有合规档案使用该管控类型，无法停用」——若允许停用则仅禁止新档案选择，已有档案仍按停用前快照或仍可读模板：一期约定 **停用后不可新建该类型档案，已有档案编辑仍按该模板校验**）
- 空态：暂无合规模板；筛选无结果：暂无符合条件的合规模板
- 分页：同主数据其他列表

##### 新建 / 编辑模板（同页弹窗）

- 标题：新建合规模板、编辑合规模板
- 字段
  - 管控类型编码：必填，最多 32 字，英数下划线；新建后不可改；重名提示「管控类型编码已存在」；空提示「请输入管控类型编码」
  - 模板名称：必填，最多 40 字；空「请输入模板名称」；重名「模板名称已存在」
  - 状态：启用/停用；新建默认启用
  - 说明：选填，最多 200 字；页面可用 `mdm-biz-tip` 提示「模板变更后，已有档案包按最新清单重新计算齐套状态」
- 清单项（方案 A：摘要列表 + 嵌套层）
  - **摘要表列**：顺序、项名称（副行可展示项编码）、来源、引用摘要、必要程度、效期预警、操作
    - 引用摘要：主体引用时展示「角色 · 允许证照类型」；档案包上传时展示「包内上传」
  - 操作：编辑、上移、下移、删除；「+ 添加清单项」后**自动打开**该项编辑层
  - 删除至少保留 1 项，否则提示「请至少保留一个清单项」
  - 关闭模板弹窗时同步关闭未保存的清单项编辑层
- 清单项编辑层（嵌套模态，盖在模板弹窗之上）
  - 业务提示：区分 **主体引用**（从供应商主体证照勾选）与 **档案包上传**（材料挂在本档案包内）
  - 主字段：项名称、必要程度、效期预警、来源
  - 来源=主体引用：展示主体角色（委托方/生产方）、允许证照类型（多选）；未选类型提示「请选择允许证照类型」
  - 来源=档案包上传：隐藏角色与类型，展示说明「本项材料在产品合规档案中由业务上传附件…」
  - 项编码收入「高级设置」：必填（可留空，确定时按名称自动生成）；模板内唯一；英数下划线；重复「项编码已存在」；提示已有档案后勿随意改编码
  - 新增项若取消且未填名称/编码：从草稿列表移除（保证不留空行）
  - 保存模板时若某项未完善：Toast 指出第 N 项，并自动打开该编辑层
- 保存成功：「合规模板已创建」/「合规模板已更新」
- 取消不保存

#### 1.2.3 供应商档案增强（资质主体 + 主体证照）

原型改造：`SCM/master_data_supplier.html`（逻辑叠加于《供应商档案》PRD）

##### 主体角色

- 在现有「供应商类型」（品牌商、代理商、个人）之外，增加可多选标签 **主体角色**：委托方、生产方（可同时具备）。

##### 主体证照 Tab（详情内）

- 详情增加页签「主体证照」。与供应商表单内「厂房照片」并存：**营业执照、食品经营许可证、法人证件等统一走主体证照**，表单/详情「厂房照片」区用 `mdm-biz-tip` 引导至此维护，避免两套证照字段并存。
- 列表列：证照类型、证号、有效期、状态、操作（编辑、作废）
- 「+ 新增证照」（嵌套弹窗，须盖过供应商详情层）
- 字段
  - 证照类型：必填；切换类型切换 OCR 识别模板与可回填字段提示
  - 证照名称：选填，默认类型名，最多 40 字
  - 证号：选填（建议执照、许可填写）
  - 发证机关、发证日期：选填
  - 长期有效：开关；为否时有效期止必填
  - 有效期起、有效期止：条件必填
  - 附件：至少 1 张图片；支持 JPG/PNG/WEBP/GIF/SVG；单张 ≤ 2MB；可多张（原型上限与实现一致即可）
  - 备注：选填
- **OCR（一期原型）**：上传附件后展示「识别中」示意与按类型的识别项说明（`mdm-biz-tip`）；**不做真实 OCR**，字段仍可手填/核对；正式环境按类型版面回填对应字段（证号、机关、日期、长期有效等），不适用字段不强行回填
- 状态计算：作废 > 已过期 > 即将过期 > 有效（规则见 1.2.7）
- 作废确认：确定作废证照「名称」？作废后不可再被新引用；已引用档案包齐套将按实时状态变差。成功「证照已作废」
- 不提供物理删除；换证=作废旧证+新增新证
- 保存提示「证照已添加」/「证照已更新」

#### 1.2.5 产品合规档案 · 新建 / 编辑

原型：在 `SCM/master_data_compliance_dossier.html` **同页弹窗**完成（可选保留独立 `…_dossier_form.html` 对照）。字段区尽量复用既有表单样式；底栏固定在弹窗 footer。

- 入口：列表「+ 新建档案包」；列表/详情「编辑」；商品详情「去创建档案包」（可带货号预填映射）
- 底栏：取消、保存草稿、保存并生效

##### 基本信息

- 档案编号：系统生成，只读；格式 `CA` + 至少 6 位流水
- 管控类型：必填；选项=启用中的合规模板；选定后加载清单；编辑时若需锁定类型则不可改（一期 **新建后管控类型不可改**，避免清单错位）
- 证照编号：必填，最多 64 字；同管控类型下唯一；空「请输入证照编号」；重复「该管控类型下证照编号已存在」
- 合规品名：必填，最多 80 字；空「请输入合规品名」
- 内部备注名：选填，最多 40 字
- 委托方：必填；未选「请选择委托方」
- 生产方：必填；未选「请选择生产方」
- 发证/备案日期：选填
- 长期有效：开关
- 有效期起/止：长期有效为否时止期必填；空「请填写有效期」
- 档案状态：草稿 / 生效；由按钮决定（保存草稿→草稿；保存并生效→生效）。列表作废→作废

##### 合规范本（只读）

- 展示当前模板清单摘要（项名称、来源、必填/选填）；提示来自模板配置。

##### 主体证引用

- 对模板中来源=主体引用的每一项：下拉选择「对应角色主体下、类型匹配、未作废」的证照；展示证号与效期状态
- 无可选证照时：空态「暂无可用证照」+ 链接「去供应商档案维护」（新开或回跳）
- 必填项在「保存并生效」时：若不允许不齐套生效，则拦截并提示「请完善：{项名称}」；若允许，则不拦截，齐套为缺失

##### 包内附件

- 对来源=档案包上传的每一项：
  - 附件至少 1 个（必填项在生效校验时）
  - 报告编号等：检测报告类可填「材料编号」（选填，最多 64 字）
  - 若项开启效期预警：有效期止必填（生效时）
  - 多文件：单项 1～N；齐套只要求 ≥1
- 格式：JPG/PNG/WEBP/PDF；图片 ≤10MB，PDF ≤20MB；不符给出明确 Toast

##### 商品映射

- 「+ 添加货号」：从基础商品库选择（建议仅「合规管控=是」且管控类型一致的商品；若选未开管控商品，确认后自动打开管控并写入本类型——一期可简化为 **仅可选已开启管控且类型一致的货号**，否则提示「请先在基础商品库开启合规管控并选择相同管控类型」）

#### 1.2.7 效期与齐套计算

##### 单证效期状态

1. 已作废 → 作废（仅主体证）
2. 长期有效或无止期且允许长期 → 有效
3. 止期 < 今天 → 已过期
4. 止期 ≤ 今天 + 预警天数 → 即将过期
5. 否则 → 有效

档案包效期状态：取 **包头** 与所有 **必填且开启效期预警** 的已填材料中，最差的一档（已过期 > 即将过期 > 有效）；若齐套为缺失，效期仍可单独展示已填材料的效期，列表「效期状态」在缺失时显示「—」或仍显示最差已填项——一期约定：**缺失时效期列显示「—」**。

##### 齐套状态（仅档案状态=生效时参与商品聚合；草稿显示「—」）

对模板每个 **必填** 项：

- 主体引用：已选证照且未作废且效期非「已过期」→ 通过（即将过期算通过，但拉低档案效期状态）
- 档案包上传：已传 ≥1 附件；若该项效期预警则止期存在且非已过期 → 通过

汇总：

| 齐套状态 | 条件                                                                                                                                                   |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 缺失   | 任一必填项未通过（未传/未引用/引用作废/必填效期已过期导致该项不通过）                                                                                                                 |
| 已过期  | 不缺失，但包头或任一行必填效期材料为已过期（若过期已在上条计入缺失，则本行可不出现；实现上「必填材料过期」一律算 **缺失** 更严——一期采用：**必填项过期 ⇒ 该项不通过 ⇒ 齐套=缺失**；「已过期」徽章用于主体证列表与选填提示；档案包列表「效期状态」在齐套非缺失时仍可为即将过期/有效） |
| 即将过期 | 必填全通过，且存在即将过期                                                                                                                                        |
| 齐全   | 必填全通过且均有效                                                                                                                                            |

选填项不影响齐套；详情可对选填过期标黄。

> 实现简化（一期采纳）：齐套枚举对外为 **齐全 / 缺失 / —（草稿或作废）**；「即将过期」「已过期」主要体现在 **效期状态** 列。列表同时展示两列以免混淆。
